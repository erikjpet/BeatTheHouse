# High Limit TEST policy and deferred entrypoints

`high_limit_spatial_test_profile.py` is a pure, versioned policy module. It has
no CLI, launcher, file reads/writes, network access or acceptance action. The
in-memory tests are source only until the parent runs them in an admitted capped
worker. No new High Limit build or served entrypoint is runnable yet.

The current independent decision is `STATIC_GO_FOR_NATIVE_TRIAL`; it does not
approve TEST delivery. Candidate R1 has the actual 21-file seal
`481e858ee3c484b06ba6df935983c29979a188e7e59ff5f44eaf22ecdbe020e4`.
The policy pins its exact nine changed PNG hashes, its JSON hash, its nine
canonical import hashes, all 16 motion IDs and the seven low-detail IDs. The only
JSON semantic changes are the five named lamp `rect[1]` integer values 124 to 8.
Every other JSON field, type, timing, geometry and ordering remains identical.

## Delivered Grand is the required baseline

High Limit must preserve the newly delivered public Grand room. Using 7b as
High Limit's direct baseline would discard that delivery. No future Grand source,
tree, manifest, PCK or served-proof hash is guessed or prefilled here.

The explicit baseline declaration requires actual source/tree, manifest/PCK
hashes, Grand approval and strict-PCK-proof hashes, Grand served proof and closed
Job hashes, canonical UID/cache/class hashes, preserved Bar seal and the observed
19-room map excluding High Limit. `check_baseline_declaration` only validates
this declaration's shape and fixed pins. Its result always states
`baseline_qualified: false`. An approval declaration likewise does not
authenticate native receipts or authorize a build.

Before implementing runnable entrypoints, independently qualify the actual
Grand immutable stage and retain a baseline certificate produced by a guarded,
read-only worker. That worker must:

1. Hash the actual immutable manifest/PCK and authenticate the Grand final GO
   approval document, with exact current source and native/art evidence.
2. Recompute the frozen Grand strict PCK proof against the immutable qualified
   7b stage, using the maintained Grand policy. Validate its complete manifest,
   all 421 raw/400 CTEX inventories, all room/doorway maps and Bar seal.
3. Authenticate the successful Grand `served.json` and its closed capped Job,
   storage manifest/claim, exact command and verifier/helper/approval hashes.
   Match its qualified-stage manifest/PCK identity to the actual baseline.
4. Verify actual default-TLS, every-file served-byte proof and final TEST pointer
   identity. An independently advanced NEXT must be reported accurately.
5. Bind the exact 1,605 UID mapping/cache bytes, class cache, compiled GD/SCN
   bytes and observed protected19-room map. Hash the certificate and preserve
   all input evidence. A supplied declaration alone must never be accepted.

The certificate format and executable consumer require review against those
actual artifacts. This module deliberately does not mint such a certificate.

## Future build entrypoint

The frozen shared build dispatch currently accepts only Bar/public Grand and
imports their room policies directly. A High Limit wrapper cannot select a new
policy through that interface. Do not monkeypatch it or identify High Limit as
Grand. Leave frozen Bar/Grand/selected-source/APNG helpers unchanged.

After the actual baseline certificate and final High Limit GO exist, add a new
High Limit-specific guarded orchestrator, reusing only generic primitives:
`bth_qa_selected_source` for exact selected Git blobs/tar/extraction and
`bth_qa_guarded_run.execute` for every explicit child. Reuse maintained identity,
TEST HTML/persistence, WebGL, PCK reader and publisher validators directly.
Every new directory/write/child requires the admitted explicit E: Layout and
unchanged budget/headroom, caps, assignment-before-resume and zero-active close.

Archive a new exact committed source with canonical imports and approved art.
Prove all actual421 source hashes and400 import/CTEX links. Compare against the
delivered Grand baseline: exactly nine High Limit CTEX payloads, its JSON and
embedded identity may change. UID/cache/class/GDC/SCN bytes stay exact. Preserve
every other room, index, doorway, native/template/engine/WebGL/persistence pin.
`verify_pck_delta` checks actual payloads but explicitly does not authenticate
baseline custody; that preceding certificate gate remains mandatory.

The build manifest activates only High Limit's exact21 seal. Its approved source
commit/tree and package must match the embedded PCK identity and final stage.
Existing generic publisher validation is still required; no publication is
performed by this policy or its tests.

## Future served entrypoint

Add a separate High Limit guarded worker after baseline/native approval. It can
reuse `HTTPSBytes`, `capture_state`, `read_before(expected_schema=...)` and
`verify_after` from the frozen served verifier as generic functions. Supply a
new High Limit schema, qualify the local stage through this policy and the
baseline certificate first, and bind actual entrypoint/profile/helper hashes.
Do not call its Bar/Grand dispatcher or pass a false environment identity.

Use the fixed site/HTTPS roots and default Windows TLS trust, with no bypass or
custom roots. Retain closed before/after Jobs; stream every manifest payload
length/hash without writing downloads. Verify managed launcher, exact current
source, immutable manifest, embedded identity and isolated TEST mount. Compare
NEXT before/after honestly. HTTPS byte identity does not establish browser
startup, native visuals, gameplay or browser acceptance.
