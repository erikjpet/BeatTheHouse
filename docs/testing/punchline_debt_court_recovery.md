# Punchline Debt Court recovery

Two independent boundaries can reject ordinary play in the club.

The club contains no wagers, but its unresolved Side Door event offers a free,
conditioned choice that discovers and enters the casino. The terminal evaluator
previously omitted that recovery and asked for event choices without the live
run/layer context. At $25 it could declare the generated club stranded even
though the authored password choice leads to affordable games. The correction
recognizes that exact event and destination, checks the actual allowed choice,
entry consequences, remaining cash and stored/catalog game availability. It
does not reopen a run already persisted as failed.

The ordinary Collector conversation and the later scripted witness request
share an event. The ordinary successful Watch/settlement result has no bridge
resolution ID. Debt Court previously subscribed only to the correlated Watch
result: typed ingress accepted an ordinary result, but application rejected it
and retained the pending fact, blocking later time-advancing actions. Two
explicit, handler-free ordinary observers now accept those authored results.
The original five-field bridge observer and all runtime correlation checks stay
unchanged. The added observers perform no payout, transition or repeated event
resolution.

## Focused evidence

The disposable legacy producer runs on clean prepatch source. It uses normal
factory, EventModule and SaveService APIs to produce an active run containing
the real rejected ordinary Watch fact. It does not manually insert a fact or
bind the run to the old terminal UI evaluator. Two normal saves preserve a
primary/backup generation and the authority/profile companions locally.

The fresh host check covers the available recovery, ordinary Watch, subsequent
turn, strict negative event-result authorization, rendered hearing actions and
later witness command, free Side Door entry, another casino game and normal
Save. Cold checks install byte-identical copies of the preserved synthetic
companions, use normal Continue, settle the old fact once, resave and Continue
again. Original fixture hashes must remain unchanged.

The sealed old club requires a raw base-authority proof before restore. The
ordinary casino has no active scenario seal; its raw slot-cache diagnostic is
retained, while normal `from_dict`/Continue rebuilds derived placement using the
trusted catalog. Both cold checks require a strict published room join after
Continue, unchanged cash/clock/RNG and archived club seal, usable room objects,
and exactly one receipt for the original Watch fact.

All four focused stages passed on 2026-10-21: the clean prepatch producer,
fresh host interaction, cold legacy recovery/resave, and cold resaved casino
Continue. The last stage published 11 usable room objects and entered/returned
from video poker with $25, the original clock/RNG, the archived club seal and
one Watch receipt unchanged. The existing strict negative event authorization
checks and later correlated witness command also passed.

The scripts are `punchline_legacy_pending_prepare.gd` (requires the pinned old
source), `punchline_witness_chairs_repro.gd`, and
`punchline_cold_recovery_check.gd` in `scripts/tests`. Each requires explicit
stage/authorization arguments and a supervisor-supplied disposable `user://`
path before it loads game or profile state. The qualification used fresh
processes, a 12% kernel workload cap, a 2 GiB Job limit and finite deadlines.

These checks use bounded private native processes with Dummy audio. They do not
constitute visual Web verification. Synthetic fixtures, root authority and
profile bytes must stay outside Git. The user's live Punchline/Gas save was not
exported; the exact cause of that live state remains unconfirmed. A passing
source/native regression must not be presented as an inspection of that save.
