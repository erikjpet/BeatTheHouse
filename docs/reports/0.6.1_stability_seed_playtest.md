### Stability issue BTH-061-STAB-001: unrelated broadcasts exhaust a room scenario journal

- Seed: `BTH-061-STAB-B01-001`.
- Initial conditions: fresh isolated profile and no save, default content,
  exact seed entered through New Run, and the Clean route selected from public

Exact reproduction:

1. At the source checkout above, run
   `powershell -ExecutionPolicy Bypass -File tools/rw06_2_ending_replay.ps1 -Ending clean -Seed BTH-061-STAB-B01-001 -ConfirmationOnly`.
2. Let the public-input route travel normally, enter and leave game surfaces,
   resolve interruptions, and preserve its mid-route Save -> quit -> relaunch
   -> Continue checkpoint.
3. In Grand Casino during the convention-crowd arrival phase, continue normal
   Blackjack play. On environment turn 99, play the visible K/5 hand and Hit;
   the drawn 10 produces a visible bust.
4. Attempt to settle the completed hand through the rendered Settle action or
   allow the autonomous settlement tick to run.

Expected: the Blackjack hand settles, its wager/economy result is applied,
and the Clean route remains playable.

Observed: the hand stayed in `settling`; the notice remained `Cards finish
moving before payout`, and the public failure message reported that the room
could not complete the action. Repeating Settle did not change public state.
The engine log contained no script error. The preserved save held scenario
`grand_casino_convention_crowd` in active `arrival`, environment turn 99, with
254 fact receipts and one visit receipt. A direct next-turn probe failed with
`scenario causal journal lifetime limit reached`.

Root cause: `RunState.scenario_enqueue_fact()` retained every public
game/town/heat broadcast for an active room sequence. The convention-crowd
sequence subscribes only to `game_result` and `travel_departed`, but unrelated
broadcasts consumed the strict 256-entry causal journal without creating a
replayable scenario cause.

Fix: accept but do not retain fact types outside the sequence's authored
`fact_subscriptions`; preflight a `world_boundary` receipt only when the active
sequence actually subscribes to it, and treat terminal sequence state as
inactive. The strict receipt budget, deterministic RNG, save schema, payouts,
and animation scheduling are unchanged.

### Stability issue BTH-061-STAB-002: simultaneous Grand Casino events hide House Calls

- Severity: High; deterministic Rourke-route progression blocker. No crash,
  payout error, RNG drift, or save corruption was observed.
- Source commit: `9f813505179944d463cdc1a7b6381e85e2ee2122`.
- Seed: `BTH-061-STAB-B02-001`.

  exact seed entered through New Run, and the Cheat route selected through
  public route support.
- Original profile:
  `.tmp/rw06_2/confirmation_profiles/cheat-20261018-161152-376-31316`.
- Original session:
  `.tmp/agent_playtest/2026-10-18/resetb-cheat-31316-b9f2d4f15e`.

Exact reproduction:

1. At the source commit above, run
   `powershell -ExecutionPolicy Bypass -File tools/rw06_2_ending_replay.ps1 -Ending cheat -Seed BTH-061-STAB-B02-001 -ConfirmationOnly`.
2. Allow normal travel, games, interruptions, economy changes, and the
   mid-route persistence checkpoint to proceed through public controls.
3. Reach Grand Casino with $69 cash, 49 chips, and heat 79 after action 135.
   Cass First Contact, Comped Suite Offer, and The House Calls are all live.
4. Attempt the required `The House Calls: Follow Rourke` interaction.

Expected: The House Calls is a rendered, selectable room object whose visible
room action enters Rourke's back-room sequence.

Observed: public semantic state listed The House Calls as visible, enabled,
and interactive, but it had no rendered canvas object or room action. Only the
other Grand Casino people were available, and the route stopped with `The room
does not expose More room actions while 'The House Calls: Follow Rourke' is
needed.` Save -> quit -> relaunch -> Continue reproduced the same missing
interaction.

Root cause: the saved room simultaneously contained three live
`behind_counter_person` events (`chain06_cass_first_contact`,
`comped_suite_offer`, and `the_house_calls`), while Grand Casino exposed only
two compatible event slots. Cass and House Calls shared slot 1, so deterministic
layout generation failed closed and the UI retained semantic records without
authoritative room geometry.

Production fix: give `event:the_house_calls` its own Grand Casino pit-boss slot
at the previously reviewed right-table position, remove it from Cass's slot,
and map it to `event.behind_counter_person_3`. This changes only production
room data; payout rules, deterministic RNG, saves, animations, and route logic
are unchanged.
