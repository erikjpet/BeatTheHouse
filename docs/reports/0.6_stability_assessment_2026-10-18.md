## BTH061-001 — Main Menu loses unsettled Coin Pusher progress

**P1, confirmed in two normal runs of the shipped Web build.**

| Seed | Ordinary route | Before Drop | Paid Drop / Menu | Continue |
| --- | --- | ---: | ---: | ---: |
| `BTH061-STABILITY-B` | Back Alley → Bar → Quarter Falls | $97 | $96 | $97 |
| `BTH061-STABILITY-D` | Back Alley → Corner Store → Quarter Falls | $97 | $96 | $97 |

Hold/release DROP once, immediately open Menu, choose Main Menu, then Continue.
The debit and the drop disappear. Both cases retained exactly the older save
before and after Main Menu, verified by decoding the packed storage envelope
and checking its SHA-256. This is a rollback to a previous valid save, not a
malformed-save rejection or a legitimate gambling loss.

The source calls the forced save before settling the machine. That save
reports success while deferring the write, and the caller then settles and
discards the session without another durable write. See
`scripts/ui/foundation_main.gd` functions `_autosave_foundation_run()` and
`return_to_main_menu()`, and Coin Pusher's `foundation_save_ready()`.

Screenshots: [Bar paid action](evidence/0.6_stability_2026-10-18/b-paid-menu.png),
[Bar rollback](evidence/0.6_stability_2026-10-18/b-after-continue.png),
[Store paid action](evidence/0.6_stability_2026-10-18/d-paid-menu.png),
[Store rollback](evidence/0.6_stability_2026-10-18/d-after-continue.png).

Control: the cabinet's Leave path eventually completed settlement and returned
to the room with the debit still visible. Do not count the early control's
browser restart as a successful persistence test: its batched navigation did
not establish the intended Main Menu boundary. The fixed candidate still needs
a correctly observed Leave → save → cold Continue control.

The shared native-close path is a high-confidence code lead, **not yet a
reproduced Windows failure**. The other two cabinet types and paid feature/tray
outcomes also remain to be tested.

## BTH061-002 — failed save still discards the live run

**P1 conditional on unavailable storage, confirmed by isolated fault injection
through the production source lifecycle.**

Seed `BTH061-SAVE-FAILURE`: save the $100 start, retain the isolated save
directory and replace its path with a regular file. Select Bar and complete
normal production travel, reducing cash to $97, then request Main Menu. The
write reports error 12 / `temporary_open_failed`. Although the status says
“Autosave failed. Retry from Run Menu or after another action,” RunState is
cleared. Restore the retained directory and Continue: the old $100 start loads.

The result and setup/outcome checks are in
[save-failure.json](evidence/0.6_stability_2026-10-18/save-failure.json).
This probe exercised the production travel and menu methods with a controlled
filesystem fault; it was not an ordinary-input route qualification and does
not establish a failure on healthy storage. Main Menu must honor save failure
and retain a recoverable live session. Exit/window-close parity needs testing.

## Useful checks and remaining limits

- Seed A: normal Back Alley → Bar → Gas Casino → Lounge travel, a paid Slot
  spin, and a full browser close/reopen/Continue. Cash $85, Heat 1, and the
  generated Gas Casino room restored correctly before continuing to Lounge.
- Seed B: normal travel through Bar, Gas Casino and the Lounge's Bachelorette
  Storm scenario also succeeded in the rendered source session. Vic's lender
  interaction opened. These are bounded checks, not completed ending routes.
- The Gas Station Numbers Book label wrapped fully in the actual package;
  the old clipping report was not reproduced in that view. No placement change
  is justified by that old report alone.
- Paused replay pointer actions did not establish accepted paid Coin Pusher
  input. Those attempts are excluded from the bug evidence; the valid payment
  reproductions above used the actual package with live mouse input. Source
  Video Poker preview/resume observations are also insufficient to establish
  loss of a paid hand and are not promoted into a bug.
- C/D/E catalog discovery used prevalidated travel. Only D was subsequently
  exercised through a normal package route; catalog rows do not count as
  player route completion.
- No engine script errors or browser page errors were recorded in the inspected
  events. Restart-related aborted requests remain in the raw log; successful
  captures do not turn those into a universal browser-network pass.
- No new performance qualification or optimization is claimed. Existing native
  Windows Smoke evidence passed unchanged budgets during release preparation;
  prior Linux/Wine misses and older non-binding reports do not establish a
  newly reproduced Windows/Web performance defect. Current baseline and
  constrained-profile measurements remain explicit tasks.
