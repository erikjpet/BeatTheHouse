# 0.6.1 save-durability fixes

Verified 2026-10-18. Implementation commit:
`ead68563a3fe2a5c548144b4e42681f74abd16ef`.
This closes the two confirmed save-loss root causes from the
[0.6 assessment](0.6_stability_assessment_2026-10-18.md). It does not close the
[remaining stability release tasks](../plans/0.6.1_stability_release_plan.md).
The published 0.6 tag and assets remain unchanged.

## Player behavior

A paid Coin Pusher drop followed immediately by Main Menu now settles and
checkpoints the machine before writing the latest run. The game clears the
live session only after that synchronous write succeeds. Both original
Quarter Falls reproductions retain $96 through Continue and a full browser
restart, instead of returning to the earlier $97 save.

When storage fails, Main Menu, Exit and native window close keep the run open
and show: “Could not save the run. Your run is still open; choose Save to
retry.” Save keeps its menu open when the machine is still settling or the
write fails. Restoring storage lets the player retry without losing the live
cash, machine or tray. Run-report Home and New Run also honor the save result.
A failed tutorial still offers its existing lesson replay behavior.

## Implementation

`FoundationMain._save_foundation_run_before_leaving()` owns the checkpoint and
final write. It preserves the active machine binding during the operation,
handles a live machine without a retained UI projection, cancels an obsolete
yielded cabinet-exit operation, and invalidates deferred HUD refresh work
before changing authority. If writing fails, the settled authoritative state
remains available for retry.

Forced autosave now returns false when the machine is not ready; synchronous
`ERR_BUSY` also returns false. Ordinary deferred autosave can still queue.
Godot's automatic quit is disabled so the close notification uses the same
save gate. No solver, odds, payouts, placements, save format or animation
scheduling changed.

The new `save_navigation_durability_check.gd` is registered in Audit and Full;
it does not expand Smoke. It checks actual production travel and paid-drop
input, complete parsed machine/tray state, RNG and cash after disk round-trip,
isolated storage failure/recovery, terminal New Run, and failure during a
yielded cabinet Leave. It verifies the retained primary/backup hashes and
rejects premature process exit. Parsed numeric values are compared because
JSON can serialize the same value as `4` or `4.0`; no expected gameplay hash
was refreshed.

The same focused regression fails against the unchanged 0.6 runtime with 15
assertion failures and no GDScript errors. On the fixed commit it passes,
including both failing seeds and the storage-recovery cases. The source tests
use Godot 4.6 and the release's existing native library in isolated profiles.

Windows x64 and Web exports were rebuilt separately from the clean fix commit
with source, engine and native-library hashes retained. The Web PCK SHA-256 is
`79c8c52eb2956b8ae4f08aba1e37dca887a258e714ac655b189bd1b4cfe9f0f9`;
the Windows EXE SHA-256 is
`6a4b50f93d24446fd26530f308da970d6d96c176f023c06882b0bb96d66eda2a`.
These are internal verification candidates, not final release packages or a
new official version.

Normal browser input reproduced each original route in the fixed package:
`BTH061-STABILITY-B`, Back Alley → Bar → Quarter Falls, and
`BTH061-STABILITY-D`, Back Alley → Corner Store → Quarter Falls. In each,
Drop charged $97 → $96, Main Menu reached the actual start screen, Continue
showed $96 and the saved Drop, and closing/reopening the complete browser
context retained the same durable save. IndexedDB saves were independently
decoded and their packed-state hashes verified. The D run began by loading an
unedited, genuine 0.6 save copied with its existing browser profile. The B run
used normal Run Setup and travel; its machine was entered with the supported
Enter key after inspection.

The exported Windows EXE, running under Wine 11/Xvfb, loaded a copied genuine
0.6 Video Poker save at $88. A normal new B run then received a real Win32
`WM_CLOSE`; the process exited, its durable save contained that newer run at
$100, and reopening/Continue restored it. Separate production-source probes
also confirmed paid-drop persistence through Exit on Linux and the close
notification on Windows. These probes do not substitute for a real Windows
close during live paid physics.

## Evidence and remaining limits

[Curated evidence](evidence/0.6.1_save_durability_2026-10-18/summary.json)
contains decoded save observations, test/build records and screenshots, with
[checksums](evidence/0.6.1_save_durability_2026-10-18/SHA256SUMS.txt).
Raw profiles, save files and local authority keys are excluded.

Only Quarter Falls has the normal-input paid-drop package retests in this
batch. Other cabinets, queued drops, payout/item conservation, live browser
reload, real Windows close during paid simulation, all-game interruption
coverage, full profile/meta inventory compatibility, performance measurements
and final fresh-package audits remain on the release plan. An exploratory
Leave control had overlapping controller requests and is excluded from
qualifying boundary evidence. Earlier B attempts that only inspected a
machine and never debited cash are likewise excluded.

The seven final regression runs reported no errors or warnings. The separate
immediate-exit source probes passed their persistence assertions but emitted
an ObjectDB leak warning during fixture shutdown; they are not clean-shutdown
qualification. Windows GUI launches emitted the existing Xvfb DRI3 warning.
Web staging regenerated missing UID sidecars; Windows export reported absent
Android build-tools. Both exports succeeded. One browser-context closure
aborted an in-flight PCK request; no GDScript/page error was reported. No
performance or full release-readiness claim is made.
