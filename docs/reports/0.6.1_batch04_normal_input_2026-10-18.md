Base: confirmed main `f0bdc406af525ed132c816d06aea6c9ddde6f60b`.

`_scenario_authoritative_environment_for_finalization()`. Verified file SHA-256:
`ebf52dd1bb178b33db59e5019acbdbd65b1a7ad269f4f969d4749b7991b45ca6`.

the live item and merchant membership, but later scenario finalization tried
to authenticate that smaller live collection as the room's immutable entry
baseline. Its strict original inventory proof no longer matched. Invitation
resolution rolled back; cold Continue could not rebuild the physical room.

inventory only on the detached baseline used for authentication. Matching
inventory version/digest references are required, and the existing complete
original-digest and geometry checks remain unchanged. Nothing is added back to
live stock. The sold offer does not reappear, and no active/rendered merchant
is restocked. The player's cash, item count, prices, RNG and scenario progress
are not rewritten. No save-schema field, placement, payout, canvas scheduling,
test, fixture, validator, golden, or harness was changed.

Verification used the same unchanged isolated command-file bridge, normal game
inputs and screenshots. The original profile backups were retained. This was
