# 0.5 Extreme-State Stability Audit

Date: 2026-08-07

## Verdict

The audited runtime passes the extreme-state, full-sample performance,
determinism, and accelerated three-hour retained-state gates. The final soak
has no retained memory, object, node, resource, orphan-node, cache, or save-size
growth signature. This is evidence for the tested state matrix, not a claim that
an arbitrary future content change can never introduce a regression.

## Scope

- Static inventory: 162 runtime `.gd`, `.json`, `.tscn`, and `.tres` files,
  including all 138 runtime GDScript files; 168,097 runtime lines.
- Parse/load inventory: every runtime script and every tool script passed the
  full-suite per-file parser; the editor import completed with no script error,
  parse error, engine warning, orphan warning, or deprecated-engine warning.
- Hot-path review: `_process`, `_physics_process`, `_draw`, animation scheduling,
  environment selection/focus, inventory construction, collection/home models,
  save/load normalization, all game resolve paths, dialogue/event queues, and
  persistent history/cache writers.
- Pathological states: 2,000 permanent items; 10,000 malformed duplicate run
  inventory entries; 10,000 story, environment, event, pending-bag, and ATM
  notification entries; repeated runs/travel/revisits; save/load cycling;
  autoplay; pinball caches; ticket piles; long baccarat roads/shoes; and previous
  multi-hand video-poker results.

## Root causes fixed

### Permanent collection and meta home

- Collection reads normalized and deep-copied the complete permanent store on
  almost every getter. UI construction called many getters, multiplying the
  work.
- The meta interaction cache key deep-copied and JSON-serialized the complete
  owned collection, bags, containers, and loadout on each cache check.
- Item sale quoting searched the full owned list and created a new collection
  resolver for every row. The interaction model therefore became quadratic.
- Collection grouping copied the growing group array for every append.
- Meta home created one animated environment object per unopened bag with no
  visible-object limit.

Fix: normalization now occurs at load/save/migration boundaries; owned item and
bag IDs have indexed lookups; the resolver is shared; UI invalidation uses a
constant-size revision key; model grouping appends in place; badges are bounded
and cached; and the home renders at most eight bag objects with an aggregate bag
shelf leading to the complete paged browser.

### Run inventory and persisted growth

- Inventory detail construction rescanned the entire inventory once per row to
  rediscover the selected active item.
- Item-effect queries repeatedly scanned the full inventory and rebuilt owned
  lookups.
- Malformed duplicate string inventory records survived restore and could turn
  UI model building into unbounded work.
- Permanent sale/trade histories, pending events, pending bags, ATM interest
  notices, and item-found popup work could grow without a local cap.

Fix: selection is resolved once per model build; item-effect totals and owned
  lookups are invalidated caches; impossible string/permanent-instance
  duplicates are removed during restore; and all listed queues/histories have
  explicit bounds. Existing legitimate per-instance item dictionaries remain
  distinct.

### Ticket and table-game paths

- Current scratch machines re-ran stock and migration normalization on every
  purchase.
- Pull-tab purchase deep-copied every deal, every remaining sleeve, and the full
  tray to buy one ticket.
- Baccarat copied and reversed the full road history and copied the full discard
  pile merely to count it. It also rebuilt/copies rules and patron state more
  often than needed.
- Current video-poker state deep-copied and normalized the complete previous
  multi-hand result on every surface read and draw, then copied it again on
  persistence.

Fix: current-schema states use cheap validation/ownership shells while old or
malformed saves retain the full repair path. Pull-tabs copies only the selected
deal shell; baccarat reads bounded arrays directly; and immutable video-poker
hand payloads are reused within one result.

### Persistent 12-cabinet slot run

The specialized slot storage gate and its uninterrupted 180-minute, same-run
soak also passed. The room was never replaced with a fresh state: 504 actions
and 21 save/load cycles ended with nodes flat at 934, zero orphan nodes, retained
memory +4,385,916 bytes under the 32 MiB gate, a maximum 109,593-byte save, and
at most 3,091 bytes per settled machine in the scale probe. Completed animation
timelines and static reel strips were absent from persisted machine state.

## Deprecated and redundant code decision

Removed confirmed uncalled private helpers from the meta interaction model,
inventory container surface, run inventory screen, and the obsolete Buffalo
ways implementation. Compatibility entry points, legacy save codecs, ticket
migrations, and old environment migrations were intentionally retained: they
are not current gameplay paths, but deleting them would break existing saves or
authored content. No current Godot deprecated API warning was emitted.
