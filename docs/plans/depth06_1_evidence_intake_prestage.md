## Random sample selection algorithm

Sample values cannot be generated until the exact landed closure candidate is
fixed. The final auditor must use this deterministic, reproducible algorithm:

1. Read the 55 ids from the landed machine-readable catalog and group them by
   canonical archetype id. Reject a catalog whose stable-id set differs from
   the accepted contract before sampling.
2. Sort archetype ids and scenario ids by unsigned UTF-8 byte order.
3. Bind `candidate_head`, the SHA-256 of the catalog bytes, and the literal
   sampler version `depth06_1-random-v1`.
4. For each archetype independently, compute the byte stream from consecutive
   SHA-256 blocks of
   `depth06_1-random-v1\n<candidate_head>\n<catalog_sha256>\n<archetype>\n<counter>`.
5. Perform a Fisher–Yates shuffle of that archetype's sorted ids. Draw each
   required integer with rejection sampling from four unsigned digest bytes;
   reject values outside the largest multiple of the current range to avoid
   modulo bias. Continue digest counters as needed.
6. Select the first two distinct ids after the shuffle. For archetypes with
   fewer than two ids, select all and report the contract failure separately.
7. Union those random selections with every mandatory high-risk case below.
   A high-risk case appearing in the random pair remains both random-selected
   and mandatory; do not replace it to make the sample look broader.
8. Publish candidate head, catalog hash, sorted inputs, digest blocks, swaps,
   selected ids, implementation/command, and an independently reproduced
   selection manifest.
