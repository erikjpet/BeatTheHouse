**No: the project has not completed everything promised for 0.5, and the
current source is not a release candidate.**

Scratch Tickets, lottery restocking and the scalper encounter, Sal's resale

conversation/run-end cleanup, UI redesign, Web/audio closure, and the runtime

identity is consistently `0.5.0`, and the collection metadata check passes.

of the tutorial playtest pass and never executed, committed regression failures,
a false-green script-load gate, an uncommitted integration workset, the
human-only tutorial/owner decisions, and packaging/publication.

## Binding gap-closure plan

1. **Reconcile the current worktree.** Finish, verify, and intentionally commit
   or explicitly defer the narration/audio-bus work. Do not discard it. Begin
   candidate testing only from a clean, committed source identity.
2. **Restore trustworthy release gates and fix committed regressions.** Execute
   `v05_release_gate_truth_and_regression_prompt.md`: fix the travel/content
   failures, map focus animation, off-tree focus, anchor warning, leaks/errors,
   and the false-green GDScript load check at their causes.
3. **Complete the inventory promise.** Execute and archive
   `tutorial_inventory_rework_prompt.md`, coordinating its item-copy portion
   with the reconciled narration rollout.
4. **Complete meaningful destination decisions.** Execute and archive
   `tutorial_meaningful_decisions_prompt.md`; preserve the existing tutorial
   fork while implementing legible, data-backed whole-run tradeoffs.
5. **Refresh performance and fidelity on final code.** Run every binding
   performance, liveness, soak, determinism, Web, visual, strict-input, and
   storage gate without waivers; then archive the performance prompt.
6. **Perform human tutorial acceptance.** Five cold players, including two
   without Blackjack knowledge, must meet TUT-N17. Archive the tutorial prompt
   only when the measurements and observations are recorded.
7. **Build the exact release candidate.** On one clean commit, execute the full
   RC prompt, refresh all captures, record the collection `draft` decision,
   complete owner Web/Windows play, and approve or reject that exact hash.
8. **Package and publish only with explicit owner authorization.** Build and
   test Web/Windows artifacts from the approved hash, record SHA-256 hashes,
   upload, publish, create `v0.5.0`, and reconcile the public records.

No historical green report, owner decision, or package may be silently carried
across a later code change. Any fix after RC approval creates a new candidate
and reruns the affected matrix.
