# 0.5 UI Full Redesign Report

## Final-state summary

The overhaul keeps the neon-pixel identity and authoritative gameplay model while replacing legacy run text with a structured HUD, data-driven room headers, a single risk dock, content-fit popups, portrait conversation presentation, and spatial inventory/sale showcases. Focus and hover are previews; committed selection and arm/confirm states remain explicit. The implementation uses the shared token/widget system and the artist-swappable raster manifest.

## Authoritative behavior audit

- Item identity, prices, collection floats, effects, container capacities, sale/pawn/redeem/repair outcomes, arm/confirm tokens, saves, and RNG continue to come from the existing services. UI-only breakdown fields sum to the already-authoritative quote.
- Bag, Backpack, Suitcase, and Trunk use open-interior art and authoritative capacities of 3, 5, 7, and 10 selectable spaces.
- Every owned item and unopened bag remains reachable through spatial containers. Focus/hover never moves the container or commits the action.
- Inspect, active item, merchant, repair, pawn, redeem, placement, home transfer, meta loadout, bag reveal, Sal sale/buyback, and trade-up retain the shared container language.
- Sal’s six shelf items remain physical room objects.
- Existing snapshot fields and legacy run entry points remain available.
- Career/stats now has its own start-screen surface. A future meta-home
  scrapbook object can attach by calling `open_career_stats_screen()` and
  reusing the same component/model path.
- P2.2 token sweep migrated visible start/run chrome in
  `foundation_screen_builder.gd` and the tutorial `coach_overlay.gd` to
  `VisualStyle`/`FoundationWidgets` tokens. The token gate now
  auto-discovers `scripts/ui/*.gd`; art canvases, diagnostic overlays,
  placement view models, and legacy modal geometry are explicit exemptions
  with one-line justifications in `tools/ui05_token_adoption_check.ps1`.
  Before/after token-count capture:
  `.tmp/ui05_captures/p2_2/token_sweep_before_after.json`.
- No intentional deferrals remain. Future polish should be additive, not acceptance work.
