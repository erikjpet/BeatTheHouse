## Release verdict

**NOT RELEASE-READY.**

Typical native and throttled-web play is within the existing frame-time budgets, all required animated surfaces clear their liveness floors, determinism is unchanged, every FoundationSuite is green, strict rendered mouse play is green, and all scratch-ticket RTP bands pass. The full retained-state soak is the sole release blocker:

`memory_static_bytes post-warmup retained slope 279116.400/sample exceeded 262144.000/sample.`

That is 16,972.4 bytes/sample above the unchanged limit. The retained fixture has flat object, node, resource, cache, serialized-state, and orphan counts; extending the settle from 30 to 180 frames produced the same result. The remaining growth therefore looks like allocator/static-memory capacity growth rather than an accumulating game object identified by the available diagnostics. It has not been proven bounded, so the required soak gate remains red.

At audit completion, the work below was left uncommitted and unpushed as the
execution prompt required. A later user instruction explicitly authorized
landing all pending branches and content on `main` before the remaining cleanup
and final tests. That later landing does not turn this audit into a release pass:
the prompt remains active under `docs/todo`, and the soak blocker remains open.

## Hot-path allocation audit

### Video poker and scratch tickets

- `video_poker.gd` and `scratch_tickets.gd` use deep copies at generation, purchase, action, or external snapshot boundaries, not inside render-frame paths.
- Scratch pointer motion is coalesced and applied as shallow state patches. Final pointer cost is 0.398 ms average / 0.412 ms p95 / 0.602 ms max against 0.750 / 1.500 / 5.000 ms budgets.
- No simulation or seeded outcome code was changed.

### Shared rendering

- `game_surface_canvas.gd` performs one shallow state copy on state replacement, applies realtime state as key patches, returns the live realtime state directly, and coalesces captured pointer moves.
- The expensive `current_view_snapshot()` remains an explicit diagnostic boundary. Performance-probe `full_snapshot_calls` stayed zero.
- `pixel_scene_canvas.gd` snapshots only when the environment render state changes and uses bounded texture caches.
- Normal play telemetry remains off unless explicitly enabled with performance arguments.

### SFX

- Web procedural prewarm no longer allocates/fills entire WAV sample arrays in a single frame.
- Each active cue has one preallocated `PackedByteArray`; the incremental writer fills it in place.
- Cancellation clears active web prewarm state safely.
- Soak diagnostics now expose queued and active prewarm state.

### Cleanup

- Audited shipping scripts for stray debug output; remaining output is test/performance telemetry or intentional diagnostics.
- Removed no `.tmp`, `.tools`, or build artifacts.
- Found no dead hot-path block that could be removed safely without expanding scope.
- Source delta: 6 files, 124 insertions, 18 deletions, plus this report.

## Plain smoothness assessment

Native play and the 4x-throttled web build are smooth within every measured interaction and frame budget. The web start-menu hitch was real, reproduced, traced to procedural SFX prewarm, and reduced from roughly 145.7 ms p95 to 10.1 ms p95 without weakening a budget. Active cabinets, scratch input, Grand Casino room churn, meta screens, and long scripted play do not show a measured stutter or liveness loss.

The game cannot yet receive the requested unconditional pre-release smoothness verdict because the 180-minute retained-state soak still shows unexplained static-memory capacity growth above the release limit. No progressive frame slowdown accompanied it, but bounded long-session memory behavior has not been proven.
